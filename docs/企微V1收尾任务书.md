# 任务书：企业微信 V1 出向通知收尾（ztl-symphony）

> 下发方式：在 claude.ai/code 对 **yangxiyun/ztl-symphony** 仓库开云端会话，把本文整段贴给它。
> 背景权威：ztl-mp `docs/企业微信接入方案.md`（V2 入向发单已因大陆备案域名门槛放弃，企微只保留 V1 出向通知）。

## 背景

MP 平台的派单入口维持 Telegram + claude.ai App 两条（均已通）。企业微信**只做 V1 出向通知**——任务完成/卡住/待决策时，把摘要推到一个企微群机器人。V2 入向发单（云函数回调）已放弃，相关代码在 `feat/wecom-gateway` 分支保留但不部署。

## 目标

orchestrator 在三个时点（任务完成 DONE / 卡住 ERROR·park / 待决策 GATE_CONFIRM·MISSING_INPUT）把一条 ≤8 行的摘要 POST 到企微群机器人 webhook。与现有 Telegram 通知**并行**，不互相替代。

## 交付

1. **核对/整理 V1 推送模块**：`feat/wecom-gateway` 分支里应已有群机器人 webhook 推送封装（V2 会话产出）。把它从 V2 的云函数代码里剥离出来，做成 orchestrator 可直接调用的独立模块（如 `gateway/wecom-notify.js`），**不依赖任何 V2 云函数 / 回调 / 备案相关代码**。
2. **接入事件流**：orchestrator 现有向 Telegram 推送通知的三时点，同处加一条企微推送（读环境变量 `MP_WECOM_WEBHOOK`，未配置则静默跳过，不报错、不影响主流程）。
3. **消息格式**：遵守汇报纪律——三段 ≤8 行（①一句话结果 ②【待决策】无则省 ③下一步）。企微群机器人 `msgtype=text` 即可，无需富文本。
4. **删干净 V2 部署残留的误导**：`docs/企业微信网关部署.md` 顶部加醒目标注「V2 已放弃，本文仅存档；生产只用 V1，见下」，或另写一份 `docs/企微V1配置.md` 只讲 webhook 配置。避免下一个读者又去建云函数。
5. **合并**：改动提交到 `feat/wecom-gateway`（或新分支），跑通后合并主干。V2 云函数代码保留备查，不删。

## 环境变量（新增一个）

| 变量 | 值 | 必填 |
|---|---|---|
| `MP_WECOM_WEBHOOK` | 企微群机器人 webhook 地址（`https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=xxx`） | 配了才推企微，不配走原有 Telegram |

配在**运行 orchestrator 的地方**（用户本地那台跑网关的电脑的 symphony 环境/`.env`，不是腾讯云）。

## 用户人工前置（已由用户操作）

- 企微建群 → 群设置「群机器人」→ 添加 → 复制 webhook 地址，交给本会话配进 `MP_WECOM_WEBHOOK`。

## 验收

- 配好 webhook 后，手动触发或跑一单，任务到达三时点之一时企微群收到对应文本消息；未配 webhook 时 orchestrator 一切照旧、无报错。

## 回报

结果一句话 + 改了哪些文件 + 用户还需做什么（配 webhook 的确切位置/命令）+ 下一步。不要长过程叙述。
